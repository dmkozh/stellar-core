## Meta-Patterns

1. **Benchmark noise gate**: Several hypotheses produced correct PoCs that passed all tests but regressed 5/6 benchmark scenarios. Independent `run_apply_load_matrix.py` reproduction is the only valid gate — test passage is necessary but insufficient. Small optimizations that save <1 µs/TX typically cannot overcome measurement noise.

2. **Dominant-cost coverage by success #001**: After the cost-params deserialization caching success, all subsequent attempts to further reduce cost-param overhead (005, 007, 014, 016) hit the same wall: the dominant remaining cost is `Budget::try_from_configs()` inside soroban-env-host, which is out of scope for bridge-layer changes.

3. **Per-TX unique vs. ledger-shared data**: The only impactful serialization optimization was eliminating O(N)-per-TX serialization of O(1) ledger-shared data (cost params). All attempts to cache O(N) per-TX-unique data (request fields, footprint entries) are ceiling-bounded at <0.5% because each is serialized exactly once.

4. **CxxBuf ownership vs. actual copy cost**: `CxxBuf` forces unique ownership (`UniquePtr<CxxVector<u8>>`), so any caching still requires a memcpy into a new owned buffer. For entries with large opaque byte fields (WASM code), that memcpy is already essentially the full serialization cost — caching only avoids the small field-traversal overhead.

5. **Benchmark config vs. standard matrix**: Several hypotheses were designed around `APPLY_LOAD_BATCH_SAC_COUNT=100` or benchmark parameters that are not used in the standard `run_apply_load_matrix.py` scenarios. Always verify trigger conditions against the actual matrix script, not standalone `.cfg` files.

6. **Per-stage vs. per-TX frequency**: Setup work that happens once per cluster (module-cache cloning, thread-state construction) is too infrequent to affect per-TX metrics. Only code paths executed for every Soroban invocation can produce measurable benchmark improvements.

7. **Zero-cost abstractions**: `panic::catch_unwind` on x86-64 DWARF, `AssertUnwindSafe`, and pointer-level CXX FFI transfers are all zero-cost on the happy path. Do not target these as optimization candidates.
